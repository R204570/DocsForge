Set up DocsForge on your machine.

Install it, check it runs, add it to your AI coding assistant, and ask your first question. DocsForge runs on your own computer with no account, no API key and no server: your client starts it whenever it needs it.

0. What you need

Python 3.11 or newerCheck with python --version — on Windows, py --version.
pipxInstalls DocsForge in an environment of its own and puts its commands on your PATH. Step 1 below if you don't have it.
Gitpipx fetches DocsForge from GitHub with it. No Git? Step 2 has a download that needs none.
An MCP clientClaude Code, Codex, Cursor, Windsurf, VS Code, Gemini CLI, Claude Desktop or Antigravity — any client that runs local MCP servers.

1. Install pipx

Already have it? Skip to step 2. Otherwise, for your system:

Windows · PowerShell
py -m pip install --user pipx
py -m pipx ensurepath
macOS · Homebrew
brew install pipx
pipx ensurepath
Linux · Debian, Ubuntu
sudo apt install pipx
pipx ensurepath

Then open a new terminal: ensurepath adds pipx's folder to your PATH, and only new terminals see it. On Fedora, sudo dnf install pipx.

2. Install DocsForge

pipx install git+https://github.com/R204570/DocsForge

Install from GitHub exactly as shown: the docsforge package on PyPI is an unrelated project, so pipx install docsforge gets you something else. Default Python older than 3.11? Add --python 3.12 (or whichever newer one you have).

No Git on this machine? The same, from a download
pipx install https://github.com/R204570/DocsForge/archive/refs/heads/main.zip

You now have two commands: docsforge-mcp, the MCP server your client starts, and docsforge, a command-line harvester you can use on its own.

3. Check it runs

docsforge-mcp --list          # prints the thirteen tools, then exits

Seeing the tools means the install worked. "Command not found" means the PATH change has not reached this terminal — see troubleshooting.

Run docsforge-mcp with nothing after it and, at a terminal, it serves this website on your own machine at http://127.0.0.1:8765, live resolver included. Ctrl+C stops it. Your client never sees that: launched by a client, the same command speaks MCP over stdin and stdout instead.

4. Add it to your client

For Claude Code, one command — --scope user makes it available in every project:

Claude Code · terminal
claude mcp add docsforge --scope user -- docsforge-mcp
claude mcp list               # docsforge should show as connected

Cursor, Windsurf, Antigravity and Claude Desktop take a config file instead. The block is the same in each; paste it into the file the client opens for MCP settings (merge it into mcpServers if you already have one), then restart the client:

mcp.json · claude_desktop_config.json · mcp_config.json
{
  "mcpServers": {
    "docsforge": {
      "command": "docsforge-mcp"
    }
  }
}

Desktop apps don't always see the PATH your terminal has. If one says it cannot find docsforge-mcp, put the full path in "command": run where docsforge-mcp on Windows or which docsforge-mcp on macOS and Linux, and in JSON write a Windows path with forward slashes — C:/Users/you/.local/bin/docsforge-mcp.exe.

Codex, Gemini CLI, VS Code and the rest: the connect page has the exact command or file for every client, ready to copy.

5. Your first question

Ask for a library by name and let the model do the rest. It never needs a URL:

you:"Use DocsForge to learn pydantic, then show me a model with a field validator."
model→ learn_technology(name="pydantic")
model→ read_knowledge_base(name="pydantic", section="validators")

The first time, DocsForge finds the official docs, checks they really are pydantic's, and harvests them — seconds for most libraries. A large manual keeps harvesting in the background, and the model can ask harvest_status how far along it is. After that every answer is read from your own disk.

Is your project pinned to an older release? Say so — learn_technology(name="pydantic", version="1.10") — or ask the model to run scan_project, which reads the versions from your package.json, pyproject.toml, requirements.txt, Cargo.toml or go.mod. Versions are stored apart, so 1.10 and 2.x never mix.

6. Where your docs live

Everything DocsForge writes goes under one folder in your home directory — C:\Users\you\.docsforge on Windows:

~/.docsforge/knowledge_base/the harvested docs: one Markdown file per library and version, plus an index
~/.docsforge/logs/a log of requests and tool calls, for when something needs explaining
~/.docsforge/resolutions.jsonwhich site each name resolved to, so a repeat costs nothing
~/.docsforge/harvests/the status of each harvest, running or finished

To keep the docs somewhere else, give the client an environment variable. DOCSFORGE_KB_ROOT moves the store; DOCSFORGE_DB set to a PostgreSQL URL stores everything in a database with ranked full-text search:

Claude Code
claude mcp add docsforge --scope user -e DOCSFORGE_KB_ROOT=D:/docs -- docsforge-mcp
a config file
"docsforge": {
  "command": "docsforge-mcp",
  "env": { "DOCSFORGE_KB_ROOT": "D:/docs" }
}

7. Update or remove

Update to the latest from GitHub
pipx reinstall docsforge
Remove it
pipx uninstall docsforge

Reinstall, not pipx upgrade: pipx never checks a GitHub install for new commits, so an upgrade changes nothing. Neither command touches ~/.docsforge: your harvested docs survive an update, and an uninstall leaves them for you to delete or keep.

8. Optional extras

Sites that need JavaScript

A few documentation sites render their pages in the browser. Add a headless browser once, and harvests can pass js: true:

pipx inject docsforge playwright --include-apps
playwright install chromium

A GitHub token

Docs that live in a GitHub repository are read through GitHub's API, which allows 60 requests an hour without a token. Set GITHUB_TOKEN in the client's env — a token with no scopes at all is enough — and the limit goes to 5,000.

9. From a clone

If you want to change DocsForge itself, work from the repository instead:

Windows · PowerShell
git clone https://github.com/R204570/DocsForge.git
cd DocsForge
py -m venv .venv
.venv\Scripts\activate
pip install -e ".[dev]"
macOS · Linux
git clone https://github.com/R204570/DocsForge.git
cd DocsForge
python3 -m venv .venv
source .venv/bin/activate
pip install -e ".[dev]"

Then, from the same folder with the environment active:

Run it: this site and /mcp at http://127.0.0.1:8765
python main.py
Run the test suite
pytest

Point your client at the clone with the venv's own Python: claude mcp add docsforge -- /path/to/DocsForge/.venv/bin/python /path/to/DocsForge/main.py (on Windows, .venv\Scripts\python.exe). A clone keeps its docs in knowledge_base/ beside main.py, not in your home folder. The contributing guide has the rest.

Troubleshooting

"docsforge-mcp: command not found"

Run pipx ensurepath, then open a new terminal. pipx keeps its commands in ~/.local/bin — C:\Users\you\.local\bin on Windows — and only terminals opened after that folder joined your PATH can find them.

My editor or Claude Desktop cannot find it

Desktop apps often start with a shorter PATH than your terminal. Use the full path from where docsforge-mcp (Windows) or which docsforge-mcp as the "command", and restart the app.

pipx install docsforge installed something else

That name on PyPI belongs to an unrelated project. Remove it with pipx uninstall docsforge, then install from GitHub as in step 2.

Running docsforge-mcp printed a web address

That is what it does at a terminal: it serves this site locally. Started by an MCP client it speaks MCP instead. Nothing needs fixing; --stdio or --http force either.

"requires a different Python"

DocsForge needs Python 3.11 or newer. Install one from python.org, then pipx install --python 3.12 git+https://github.com/R204570/DocsForge.

"git" is not recognised

Install Git, or skip it: pipx install https://github.com/R204570/DocsForge/archive/refs/heads/main.zip installs the same thing from a download.

The model says a harvest is still running

Big manuals take longer than one tool call is allowed to. The harvest carries on in the background; ask the model to check harvest_status, or just ask your question again in a minute.

Something else

Open an issue with what you ran and what it printed. The log in ~/.docsforge/logs usually shows what happened.
