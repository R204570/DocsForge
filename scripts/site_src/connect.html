Connect your MCP client.

DocsForge runs on your own machine. Install it once, add one line to your client, and the client starts it whenever it needs it — no URL, no token, no account. The same thirteen tools whichever client you use.

There is no public server to connect to. The DocsForge behind this site, at docsforge.vercel.app/mcp, is a private development deployment: it answers only to its owner's token, and tokens are not given out. Run DocsForge on your own machine, as below — or host your own, and point your clients at that.

1. Install

pipx install git+https://github.com/R204570/DocsForge

New to pipx or MCP? The setup guide walks through every step on Windows, macOS and Linux. Python 3.11 or newer. With uv instead: uv tool install git+https://github.com/R204570/DocsForge. Install from GitHub as shown: the docsforge package on PyPI is an unrelated project. Either way you get two commands, docsforge-mcp (the MCP server) and docsforge (a command-line harvester).

2. Add it to your client

One command or one config block per client. On your machine, the client starts docsforge-mcp itself and harvested docs are kept in ~/.docsforge/knowledge_base. For a server you host, paste its address and token — both are spliced in on this page only and never sent anywhere.

Runs
Claude Code terminal 
claude mcp add docsforge -- docsforge-mcp

One command. Scope defaults to the current project; add --scope user to have it everywhere.

Host it for a team

One server and one shared store for several people or machines: DocsForge over HTTP, behind a bearer token you choose, with PostgreSQL as the store. Then pick On a server you host above — or open /connect on your server, where the snippets already point at it.

export DOCSFORGE_MCP_TOKEN=…        # any long random string; clients send it
export DOCSFORGE_DB=postgresql://…
docsforge-mcp --http --host 0.0.0.0 --port 8765

Binding a public address without a token is refused. Set DOCSFORGE_MCP_INSECURE=1 only on a network you own. The repository's Containerfile runs the same thing in a container.

First conversation

you:"How do I retry with exponential backoff in Effect?"
model→ learn_technology(name="effect")
model→ read_knowledge_base(name="effect", section="retry")

The model never sees a URL. It asks for a name, reads back the pages that match, and answers from the manual instead of from memory.

Where harvested docs live

Markdown files — the default.

~/.docsforge/knowledge_base/<tech>/<version>.md (knowledge_base/ beside main.py in a clone), one file per version plus an index. Zero setup, and the file is a deliverable you can hand to anyone.

PostgreSQL — set DOCSFORGE_DB.

A row per page with a GIN-indexed tsvector: ranked search across everything stored, snippets showing why a page matched, and pagination that never loads the whole store. Several DocsForge instances can share one store.

'retry with exponential backoff' → 6 pages, ranked, 0.11s over 703 stored pages — a recorded run.

Configuration

DOCSFORGE_MCP_TOKENbearer token clients must send
DOCSFORGE_DB / DATABASE_URLPostgres DSN; files otherwise
DOCSFORGE_MAX_CHARScap on what a tool hands back (60,000)
DOCSFORGE_HARVEST_DEADLINEseconds before a harvest goes to the background (25)
DOCSFORGE_KB_ROOTwhere the file store lives (~/.docsforge/knowledge_base)
DOCSFORGE_ALLOW_DELETEenables forget_documentation (off)
DOCSFORGE_TRY0 turns off the live find_docs box on the home page (on)
